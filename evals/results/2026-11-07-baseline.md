## Repository faults the agents reported, and what was done

Confirmed against the files and fixed:
- AGENT.md named server-monitoring.md; the file is setup-server-monitoring.md. Fixed.
- The incident playbook referred to non-existent "vulnerability scanning playbooks". Removed.
- Cost guardrail had no dollar figure. Added a default ceiling ($5 for demos) and a ceiling-before-EKS rule.
- Production changes had no guardrail entry. Added a Production section.
- Unclear whether disposable demo resources need approval to delete. Clarified; client request alone is not confirmation.
- No rule against promising outcomes or blaming third parties. Added to Communication.
- Secrets playbook lacked abuse review, public-repo handling, history-rewrite guidance and deactivate-versus-delete. Added steps 5 to 8.
- Incident playbook lacked severity levels, a no-monitoring fallback and a common-causes checklist. Added.
- No playbook for customer communication or for decommissioning a client environment. Added both.

Reported but not changed (unverified or out of scope for now): a claimed contradiction between discovery and creating a billing alarm; no AWS region guidance; no manifests for the Postgres demo (they exist in the Session 36 repo); teardown-check.sh still unrun end to end; no account-setup playbook for first-time AWS users.
